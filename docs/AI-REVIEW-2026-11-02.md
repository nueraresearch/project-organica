## Five rubric questions

### 1. Is the hypothesis genuinely testable?

**Verdict: DEFECT. Severity: BLOCKING.**

The design does specify a falsifiable within-configuration rank relation, a direction, and outcomes for absence and reversal. But its pre-run endpoint-resolution gate is calculated for the wrong kind of score. Protocol §3.1 says: “The outcome is a proportion over the withheld transitions, so the endpoint’s quantum is one divided by that count.” The implementation it names does not return a proportion. `benchmarks/reusable_knowledge.py` calls `score(...)["log_loss"]`; the imported `score()` in `benchmarks/acquisition_compositional.py` computes pairwise binary log loss over each context source crossed with the vocabulary, averages that loss, and returns `log_loss` and `brier`. It does not count a proportion of correct held-out transitions. [1] [3] [4]

Therefore `1 / 106 = 0.009434` is not the score’s quantum, and the claimed `5.3`-quantum margin is not a valid resolution test for this endpoint. The protocol’s `0.05` “effect gap” is also not established by a Spearman correlation of `0.50`: the code obtains it as `2 × 0.50 × 0.05`, which assumes a linear standardized contrast that the rank-correlation claim does not define. The artifact reproduces these calculations, but reproduction does not validate their relevance to the implemented score. [2] [3]

**Check that would settle it:** before any world runs, enumerate the exact Stage B score inputs and outputs for each claimed configuration and establish the score’s actual attainable resolution and the relation-scale contrast corresponding to the declared smallest effect. The current count-of-transitions calculation does not settle that question.

### 2. Are the measurements independent?

**Verdict: CONDITIONAL. Severity: IMPORTANT.**

They are not independent instruments. The design correctly discloses that “Onset and the outcome come from one engine and one readout,” and says its size baseline and permutation control “bound that explanation; they do not remove it.” That candour is good; it does not turn the two measurements into independent measurements. The planned size baseline and within-configuration permutation are relevant controls, while the required pair-overlap guard can catch literal overlap. [1] [6]

The evidence establishes planned controls, not their results on Stage B worlds. The outcome’s actual scoring support is also broader than a list of observed transition pairs: the scorer evaluates source-tag/vocabulary pairs for each context. Consequently, the protocol’s simple description of a pair-set guard must be checked against the scorer’s actual inputs, not only against the names of withheld cell transitions. [4]

**Check that would settle it:** on the exact Stage B inputs, compute and publish the intersection between every item of DI support and every item contributing to the held-out score, alongside the precommitted size-baseline and permutation results for each configuration.

### 3. Is the held-out design valid?

**Verdict: CONDITIONAL. Severity: BLOCKING.**

The existing reusable-knowledge code has a coherent holdout mechanism: formation and revision learning use the same `WITHHELD` cell transitions, and its `held_only()` routine selects those transitions in the revision-test phase. That supports the intended separation in the calibration implementation. [3]

However, the protocol and supplied prompt point readers to `formation_provenance_study.py`’s `held_out_pairs()` and `PHASE_TRANSFER` as the definition of the transitions withheld for the behavioral outcome. That helper instead returns observed ordered tag pairs occurring in the transfer phase; it is not the `WITHHELD` cell-transition rule or the revision-test scoring selector used by `reusable_knowledge.py`. In addition, Stage B defines a behavioral window relative to each world’s confirmed onset, but the cited calibration implementation uses fixed phases. The cited code therefore does not by itself demonstrate that the exact dynamic Stage B window is disjoint from the relevant learning and predictor support. [1] [3] [7]

**Check that would settle it:** run the actual pre-world Stage B enumeration for all four claimed configurations and show, from the exact dynamically positioned score inputs, that withheld transitions are absent from both learning windows and that the DI-support/score-support intersection is empty.

### 4. Are the statistical criteria defensible?

**Verdict: DEFECT. Severity: BLOCKING.**

The protocol specifies Spearman correlation with a 10,000-replicate percentile bootstrap at 98.33%. The block-size calculator does not calculate resolution for that procedure. `benchmarks/stage_b_protocol.py::_worlds_for()` uses a Fisher-z closed form for a correlation interval. The sign-resolution artifact distinguishes those constructions: at `n = 48` and Spearman `ρ = 0.50`, its analytic estimate is `0.9018`, while its simulation of the bootstrap procedure is `0.85` (200 simulations; Monte Carlo SE `0.0252`). The artifact notes that these are different interval constructions. The Stage B planning case is still less directly covered: reliability `0.50` maps to observed Spearman `0.351510` and `n = 104`, but no result in the reviewed package establishes that the specified bootstrap achieves the stated 90% resolution at that point. [1] [2] [5] [6]

I independently recomputed the stated attenuation equation and Fisher-z formula. All eight published rows match: observed effects `0.500000, 0.473786, 0.446170, 0.416870, 0.385502, 0.351510, 0.314041, 0.271659`; corresponding worlds per configuration `48, 54, 62, 72, 85, 104, 131, 177`. The arithmetic is internally reproducible. It is not a validation of the planned bootstrap resolution, nor of the assumed endpoint effect-gap calculation. The 215,696-cycle total also recomputes from `104 × (649 + 514 + 472 + 439)`. [2] [3] [5]

**Check that would settle it:** estimate the resolution probability using the exact specified Spearman percentile-bootstrap procedure, at adequate simulation precision, for each attenuated effect and sample size in the ladder—especially `ρ = 0.351510, n = 104`—and apply the declared 90% bar. The check must use the actual interval procedure rather than substitute Fisher-z coverage.

### 5. Can the experiment falsify the hypothesis?

**Verdict: PASS. Severity: none for this item.**

The protocol precommits absence, reversal, a configuration in which onset is mostly undefined, and a pooled-only relation as outcomes that do not support the hypothesis as stated. It also distinguishes mixed results, a size-only effect, a non-null permutation control, and an underpowered result. These make it possible for the proposed evidence to count against the claim rather than being reinterpreted as support. This pass on falsifiability does not cure the endpoint-resolution or power defects above. [1]

## Five questions in Stage B protocol §10

### Block size and unmeasured reliability

The ladder is a transparent sensitivity calculation under its stated classical-error mapping; it is not an estimate of DI reliability. The protocol correctly labels reliability `0.50` as an assumption, not an established lower bound, and the 104-per-configuration figure is conditional on it. The 0.30 and 0.40 rows show that a weaker instrument implies materially larger blocks. Because the inferential calculation is Fisher-z while the protocol’s analysis uses a percentile bootstrap, the ladder does not yet demonstrate the promised resolution under the actual analysis. **Verdict: CONDITIONAL; severity: BLOCKING**, for the reason and settling check in rubric question 4. [2] [3] [5]

### Sustention-rule agreement

**Verdict: PASS.** Describing the 0.972 rank agreement as robustness to the sustention-rule choice—not reliability—and excluding it from block-size arithmetic is methodologically appropriate. The measurements use the same trajectories and are not independent repeats with independent measurement error. The construct record and protocol state this limitation rather than converting robustness into a reliability coefficient. [1] [9]

### Endpoint resolution and operational definition

**Verdict: DEFECT. Severity: BLOCKING.** The code does operationally calculate a named `revision_held_out` score, but that score is an averaged pairwise log loss, not the proportion assumed by the resolution section. The claimed one-transition quantum and the `0.05` gap therefore do not establish that the implemented score can resolve the claimed effect. The prompt’s pointer to `formation_provenance_study.py::held_out_pairs()` also does not identify the revision-test score’s actual withholding selector. The exact enumeration and score-scale check stated above are needed before endpoint resolution can be claimed. [1] [3] [4] [7]

### Seed allocation, spares, and attrition

**Verdict: PASS.** The protocol distinguishes pre-assigned from allocated seeds, names 416 planned seeds and four unused spares, prohibits substitution, and reports that its generator found no overlap with the 192 consumed seeds in 71 artifacts. The protocol test asserts those quantities and the no-substitution rule. I did not run the repository’s test suite or independently scan all 71 JSON artifacts locally; this verdict is based on the pinned generator, artifact, and test source. [1] [2] [3] [12]

### Aggregation rule

**Verdict: PASS.** Requiring the predicted result in every claimed configuration, forbidding a pooled coefficient as the finding, and labeling partial success “mixed” blocks the obvious route of selecting the most favorable configuration after seeing results. Any configuration excluded by the precommitted eligibility rule still needs to remain visible in the accounting; the protocol says it will. The rule supports only the tested eligible configurations, not a broader population claim. [1]

## Strongest single objection

If I were responsible for defending this run, my strongest objection would be that the protocol’s gate for deciding whether the behavioral endpoint can resolve its own claim is calculated for a different outcome from the one the code returns. The endpoint is scored as averaged pairwise log loss, but its resolution is defended as if it were a proportion with a one-transition quantum. The central pre-run check can therefore pass or fail for the wrong reason. The sample-size table adds a second unresolved mismatch: its closed form is Fisher-z, while the analysis promises a percentile bootstrap, and the package’s own bootstrap comparison does not reproduce the analytic 90% figure at the published 48-world floor. I cannot infer from the current artifacts that 104 worlds per configuration will resolve the declared effect at the promised rate.

## Numbers without an artifact

I found no literal protocol number that lacked a named source artifact or generator. The ladder rows, cycle estimate, seed ranges, historical onset values, and design-block counts all have identified sources. But two derived quantities are not supported for the endpoint as actually implemented: `quantum = 1 / held-out-transition-count` and the claimed `0.05` effect gap. Their presence in generated JSON and tests proves that the arithmetic was reproduced, not that the assumed proportion-scale interpretation fits the log-loss scorer.

## What would have to be true for this block to be worth 215,696 cycles

At minimum, the actual DI measurement would need to be no less reliable than the declared `0.50` planning assumption under an error model close enough to the classical independent-error mapping for the ladder to be informative; the four configurations would need to meet the onset eligibility criteria; the withheld endpoint would need to be measurable on the exact Stage B windows; and the 104-world block would need to attain the 90% resolution target under the actual planned bootstrap, without unmodeled dependence reducing it. The historical median horizons would also need to be a reasonable cost estimate for the fresh worlds. None of those empirical conditions has been established by this pre-pass. If reliability is below `0.50`, the protocol’s own ladder calls for more than 104 worlds per configuration; if the endpoint score cannot be resolved at the claimed scale, spending the stated block does not test the stated claim.
